## Standing rules learned this session (already in CLAUDE.md / memory)

- **Regenerate gstack ONLY with `--catalog-mode=full`.** Bare
  `bun run gen:skill-docs` silently collapses 40 of 57 skills to one-line
  descriptions. Memory: `reference_gstack_catalog_mode_full`.
- **Live skills are COPIES, not junctions.** A repo edit is inert until copied
  to `~/.claude/skills/<name>/`. This is what Task 2 (`/parity`) automates.
- **`allowed-tools` is ADVISORY.** Only a PreToolUse hook physically present in
  `~/.claude/settings.json` actually blocks a tool call. A `hooks:` block inside
  a skill's own frontmatter is NOT auto-registered (gstack is not an enabled
  plugin) and enforces nothing.

  **CORRECTION (2026-08-05).** An earlier version of this line cited
  `freeze/SKILL.md` as the proof. That citation was false when written: at that
  time `/freeze`'s documented Setup never wired anything into `settings.json`,
  so freeze had the *same* inert-hook defect this doc was describing —
  `.sdd/task-freeze-report.md` proved it empirically by following freeze's Setup
  exactly and then landing an out-of-boundary Edit with no block. freeze was
  fixed later the same day (`gstack-freeze-wire --install`, now at
  `freeze/SKILL.md:69-73`) and is sound today, but it was never the evidence for
  this claim. The actual proof is the installed Claude Code binary: the
  dispatcher only honours `hookSpecificOutput.hookEventName === "PreToolUse"`
  with `hookSpecificOutput.permissionDecision`. Citing a skill that was itself
  broken as the working reference is the failure mode this doc exists to warn
  about — it happened here.
- **SKILL.md is GENERATED from SKILL.md.tmpl** — edit the SOURCE ONLY
  (`SKILL.md.tmpl`, `sections/*.md`, or the resolver under `scripts/`), then
  regenerate. Do NOT hand-edit the generated `SKILL.md`: the next generator run
  reverts it silently, which has already cost one 40-skill refactor. A
  PreToolUse guard now blocks such edits.
